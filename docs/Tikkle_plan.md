## 1. 서비스 개요

> **"잔돈으로 시작하는 나만의 코인 투자"**

**티끌(Tikkle)** 은 일상 카드 결제에서 발생하는 잔돈을 사용자의 투자 성향에 맞는 가상자산(코인)에 투자해 주는 **마이크로 인베스팅(Micro-investing)** 서비스입니다. '티끌 모아 태산'이라는 이름 그대로, 커피 한 잔·배달 한 번의 자투리 금액이 사용자도 모르는 사이 자산으로 쌓이는 경험을 제공합니다.

### 1.1 문제 정의 (Problem)

자산 관리를 시작하려는 2030 사회초년생은 세 가지 장벽에 막혀 있습니다.

1. **시드머니 부족** — "몇 만 원으로 무슨 투자를 하나"라는 인식 때문에 시작 자체를 미룹니다.
2. **금융 지식 부족** — 수백 개의 코인 중 무엇을, 언제, 얼마나 사야 할지 판단할 근거가 없습니다.
3. **소비와 투자의 단절** — 기존 금융 환경은 결제와 투자를 철저히 분리해 두어, 투자가 '따로 시간 내서 해야 하는 무거운 이벤트'로 인식됩니다.

### 1.2 솔루션 (Solution)

| 장벽 | 티끌의 해법 |
| --- | --- |
| 시드머니 부족 | 결제 잔돈(수천~수만 원 단위)만으로 투자 — 별도 목돈이 필요 없음 |
| 금융 지식 부족 | 5축 투자 성향을 대변하는 **AI 대리인(AI Proxy)** 이 종목을 추천 — 사용자는 승인/거절만 결정 |
| 소비와 투자의 단절 | 결제 발생 → 잔돈 계산 → 투자 제안까지 **전 과정 자동화** — 소비가 곧 투자의 트리거 |

단, **돈이 움직이는 결정은 반드시 사용자가 내립니다.** 모든 매수는 사용자의 명시적 승인(24시간 이내)을 거치며, 자동으로 진행되는 것은 '제안까지'입니다. 이는 가상자산의 높은 변동성 환경에서 사용자 통제권과 심리적 안전감을 지키기 위한 핵심 설계 원칙입니다.

## 2. 타겟 고객 및 핵심 가치 제안

### 2.1 메인 타겟

**투자 의지는 있지만 시드머니와 금융 지식이 부족해 시작하지 못하는 2030 사회초년생.**

> **페르소나 예시 — 김정윤(27, 입사 2년 차)**
> 월급의 대부분이 생활비로 나가고, 코인 투자에 관심은 있지만 "지금 들어가도 되나?"라는 불안에 관망만 2년째. 하루 평균 3~4건의 카드 결제를 하며, 케이뱅크 체크카드를 주 결제 수단으로 쓴다. 티끌 설치 후에는 블루보틀에서 14,400원을 결제하면 5,600원(1만 원 올림 잔돈)이 투자 제안으로 돌아오고, 알림에서 [투자하기] 한 번이면 성향에 맞는 코인이 매수된다.

### 2.2 핵심 가치 제안 (UVP)

1. **소비와 투자의 연결** — 소비하는 과정에서 무의식적으로 자산을 불려 나가는 일상 밀착형 투자 경험을 제공하여 투자의 심리적 장벽을 허뭅니다.
2. **AI 대리인 기반 맞춤형 추천** — 단순 분산 투자가 아니라, 사용자의 가상자산 투자 성향 5축을 완벽히 대변하는 AI가 종목을 추천합니다.
   - ① 하락장 방어 심리(RiskTolerance) ② 트렌드 민감도(TrendSensitivity) ③ 관심 코인 테마(CryptoTheme: 메이저·DeFi·AI·Web3 게이밍·RWA·밈) ④ 포트폴리오 분산도(DiversificationType) ⑤ 밈 코인 수용도(MemeAcceptance)
3. **투명한 데이터 시각화** — 결제 카테고리(카페, 마트 등)와 연동된 소비 패턴 분석과 실시간 포트폴리오를 시각적으로 제공하여, 현명한 소비와 투자의 선순환을 유도합니다.
4. **초보자 동반 성장** — 마켓 뉴스 큐레이션, 투자 용어집, 초보자 가이드 콘텐츠(인사이트 탭)로 '투자하면서 배우는' 경험을 제공합니다.

## 3. 사용자 여정 (User Journey)

```
[가입]          휴대폰 SMS 인증 회원가입 (전화번호 + 비밀번호)
   ↓
[온보딩]        ① 케이뱅크 카드 등록 (끝 4자리)
 (8단계)        ② 업비트 Open API 키 연동 + 2차 인증 앱 선택
                ③ 투자 성향 설문 5문항 (Q1~Q5)
                ④ 잔돈 규칙 설정 (올림/비율)
   ↓
[일상 소비]     케이뱅크 카드로 평소처럼 결제
   ↓
[자동 처리]     결제 푸시 감지 → 서버 전송 → 카테고리 분류 → 잔돈 계산 → AI 코인 추천
   ↓
[투자 제안]     앱 로컬 알림: "블루보틀 잔돈 2,800원으로 이더리움에 투자할까요?"
   ↓
[승인 결정]     [투자하기] → 업비트 입금 2차 인증 → 시장가 매수 체결   (또는 [투자 취소])
   ↓
[확인/관리]     홈 대시보드(실시간 자산·포트폴리오), 결제 내역(잔돈 통계), 설정(규칙 변경)
```

여정에서 사용자가 능동적으로 해야 하는 일은 **최초 온보딩 1회 + 건별 승인 탭 1회**뿐입니다. 나머지는 모두 시스템이 대신합니다.

## 5. 핵심 비즈니스 로직 및 서비스 플로우

전체 파이프라인의 단계별 상세(상태 모델, SSE 계약, 실패 처리)는 `Tikkle_payment_investment_flow.md`가 단일 기준 문서입니다. 여기서는 기획 관점의 골격만 정리합니다.

1. **결제 감지 및 보안 전송** — 케이뱅크 카드 결제 발생 시 안드로이드 앱이 푸시 알림을 스크래핑하여 가맹점명·금액·카드 끝 4자리를 파싱하고, Replay Attack 방지를 위해 HMAC SHA-256 서명 처리하여 서버로 전송합니다.
2. **조기 차단 (Fail-Fast)** — 서명·타임스탬프 검증 후, 중복 결제(Redis SETNX)·투자 비활성·타겟 카드 불일치 트래픽을 원장 적재 전에 차단합니다.
3. **분류 및 잔돈 정산** — 가맹점명을 2-Tier(사전 → 동기 LLM) 구조로 7대 카테고리로 분류하고, 해당 카테고리에 사용자가 설정한 다이나믹 잔돈 룰(예: 카페는 20% 적립, 쇼핑은 1만 원 올림)을 적용합니다.
4. **AI 추천 및 승인 대기** — 2-Stage 퀀트 엔진이 타겟 코인 1개를 3초 내에 확정하고 `PENDING_PURCHASE`로 적재, 앱이 로컬 알림으로 승인을 요청합니다. **이 단계까지 업비트 API는 호출되지 않습니다.**
5. **승인 → 입금 → 체결** — 사용자가 승인하면 업비트 원화 입금(2차 인증) → 입금 확인(3초 폴링) → 시장가 매수 → 체결 확인(10초 폴링) → 포트폴리오 반영 순으로 진행되며, 결과는 SSE로 실시간 통보됩니다. 코인 시장은 24시간 개장이므로 언제 승인하든 즉시 매수됩니다.
6. **정리 정책** — 거절 시 즉시, 24시간 미승인 시 스케줄러가 해당 건을 미투자(`NOT_INVESTED`)로 정리합니다. 진행 중 업비트 키 만료가 감지되면 실패 처리 후 재연동을 유도합니다.

### 5.1 핵심 정책 요약

| 정책 | 값 | 기획 의도 |
| --- | --- | --- |
| 매수 방식 | **전건 사용자 승인** (자동 매수 없음) | 변동성 자산에 대한 사용자 통제권 보장 |
| 최소 투자 금액 | 잔돈 **5,100원 이상** | 업비트 최소 주문 금액(5,000원) + 수수료 여유분 |
| 승인 유효 시간 | **24시간** | 추천 시점의 시세·추천 근거가 유효한 기간으로 제한 |
| 잔돈 규칙 | 올림(1/2/3/4/5만 원) 또는 비율(10~30%) × 7개 카테고리 개별 설정 | 소비 패턴에 따른 세밀한 적립 통제권 부여 |
| 2차 인증 | 카카오톡/네이버/하나원큐 중 택1, 입금 시마다 인증 | 원화 이동의 최종 관문을 사용자 본인이 쥐도록 함 |
| 미투자 건 기록 | 잔돈 미달 건도 원장에 저장 | 소비 통계의 완결성 유지 (투자 여부와 무관하게 가계부 역할) |

## 6. 시스템 및 데이터 아키텍처

사용자 기기의 백그라운드 구동 특성, 금융 데이터의 정합성, 외부 AI API의 비용 효율성을 모두 충족하기 위해 **투트랙 보안(Two-Track Security)** 과 **2-Tier/2-Stage 비동기 처리 아키텍처**를 채택합니다.

### 6.1 기술 스택

| 영역 | 선택 | 비고 |
| --- | --- | --- |
| 클라이언트 | Vue 3 + TypeScript + Capacitor 8 (Android) | 웹 앱을 네이티브로 감싸 푸시 스크래핑 등 네이티브 기능 접근 |
| 백엔드 | Java 21 · Spring Boot | Controller–Service–Repository 계층 구조 |
| 데이터 | MySQL 8 (원장·메타데이터) + Redis 7 (캐시·멱등 키·토큰) | 실시간 결제 엔진의 잦은 설정 조회는 Redis가 흡수 |
| AI | Spring AI — Google Gemini(동기 가맹점 분류) + DeepSeek(12시간 유니버스 생성) | 용도별 모델 분리로 비용·지연 최적화 |
| 외부 연동 | 업비트 Open API(입금·주문·시세), CoolSMS(SMS 인증), Google News RSS | — |
| 실시간 | SSE(매수 파이프라인 통보), 업비트 WebSocket(홈 실시간 시세) | — |
| 보안 | JWT + HMAC SHA-256 이중 트랙, AES-256 필드 암호화, BCrypt | §6.3 |

### 6.2 결제 데이터 수집 정책 (Push Scraping)

- **수집 방식**: 서버 간 Webhook이 아닌, 사용자 스마트폰의 Notification Listener를 활용한 **푸시 스크래핑** 방식. 금융사 제휴 없이 실시간 결제 데이터를 확보할 수 있는 MVP 최적 전략입니다.
- **지원 카드**: 현재 **케이뱅크 카드 단일 지원**. 앱은 케이뱅크 앱 패키지의 결제 푸시만 필터링·파싱하며, 파싱 로직이 카드사별 정규식 구조로 되어 있어 추후 카드사 확장이 용이합니다.
- **타겟 카드 지정**: 사용자는 온보딩 시 투자에 활용할 카드(끝 4자리)를 지정합니다. 생활비·데이트 통장 등 목적별 카드 분리를 고려해, **본인이 동의한 카드의 지출에서만** 잔돈 투자가 발생하도록 통제권을 부여하기 위함입니다.
- **멱등성 키**: 가맹점명·금액·알림 발생 시각(postTime)을 조합한 **결정적 해시 기반 `transactionId`** 를 클라이언트가 생성하여, 푸시 중복 수신 환경에서도 동일 결제가 두 번 처리되지 않습니다.
- **한계 인지**: 카드사 푸시에는 계좌 잔액이 누락되는 경우가 많아 잔액 검증은 생략합니다. 앱 미설치 기간의 결제(콜드 스타트)와 OS 배터리 최적화로 인한 푸시 누락은 Phase 2에서 보완합니다(§8).

### 6.3 투트랙 인증 및 보안 아키텍처

UI 요청과 백그라운드 스크래핑 요청의 인증 통로를 분리합니다.

```
[일반 유저 요청]  ──→  JWT Authentication Filter  ──→  컨트롤러
[푸시 스크래핑]   ──→  JWT 필터 예외(permitAll)    ──→  HMAC Interceptor (서명 검증)
```

1. **일반 서비스 API**: 휴대폰 SMS 인증 기반 가입/로그인 후 JWT(Access/Refresh) 체계. SMS 남용 방지 가드(재발송 쿨다운, 일일 발송 한도, 검증 시도 제한)를 Redis로 운영합니다.
2. **푸시 수신 API**: 앱이 백그라운드/종료 상태일 때 OS 가용 시간이 극히 짧아 토큰 갱신 실패로 데이터가 유실될 수 있으므로 JWT 대상에서 제외하고, 대신 **HMAC SHA-256 서명**(본문+타임스탬프, 공유 시크릿)으로 무결성을 검증합니다. 타임스탬프 오차 5분 초과는 Replay Attack으로 간주해 차단합니다.
3. **자격 증명 보호**: 업비트 Access/Secret Key는 **AES-256 양방향 암호화** 후 저장하며, 등록·수정 시점에 5대 필수 권한을 실제 업비트 API 호출로 검증합니다. 이후의 키 만료·권한 회수는 실 호출 401 시점에 감지하여 재연동을 유도합니다(별도 만료일 컬럼을 두지 않는 단순화 설계).

### 6.4 2-Tier 카테고리 분류 시스템

비용 효율과 저지연을 동시에 달성하기 위해, 별도 메시지 큐 없이 **DB 사전 + 동기 LLM** 2단 구조를 사용합니다.

- **1차 (키워드 사전)**: 한 번이라도 분류된 가맹점은 전역 사전 테이블에 누적되어 부분 일치 조회로 즉시 확정됩니다. 유저 무관 전역 캐시이므로 **서비스가 운영될수록 적중률이 상승**하고 LLM 호출 비용은 감소합니다.
- **2차 (동기 LLM)**: 사전 미스 시 Gemini를 동기 호출(5초 타임아웃)해 핵심 상호명과 카테고리를 구조화 JSON으로 추출하고, 결과를 사전에 저장해 시스템을 학습시킵니다.
- **Fallback**: LLM 장애 시에도 결제 누락을 막기 위해 `ETC(기타)` 카테고리로 강제 할당하고 파이프라인을 무중단 진행합니다.

### 6.5 2-Stage 퀀트 추천 엔진

"결제할 때마다 무거운 AI를 부르지 않는다"가 설계 핵심입니다.

- **Stage 1 (선계산)**: 12시간마다(02시/14시 KST) LLM이 시황 데이터를 기반으로 9가지 성향 조합별 15종목 유니버스를 생성하여 Redis에 적재합니다.
- **Stage 2 (실시간)**: 결제 시점에는 캐시된 유니버스 위에서 실시간 업비트 시세, 테마 선호도, 밈 수용도, 최근 매수 이력을 AHP 가중치로 스코어링해 1순위 코인을 선정합니다. **AI 호출 없이 3초 내 개인화 추천**이 완성됩니다.
- **안전장치**: 프로필 부재·캐시 실패 등 어떤 경우에도 비트코인(KRW-BTC) 폴백으로 파이프라인은 항상 결과를 냅니다.

### 6.6 안정성 설계 포인트

- **주문 유실 방지**: 업비트에 주문이 접수된 후에는 어떤 오류가 나도 주문 UUID를 잃지 않도록 예외를 격리하고 백그라운드 폴링으로 추적을 이어갑니다. 주문 identifier를 결제 건당 고정(`tikkle-{eventId}`)해 중복 주문도 원천 차단합니다.
- **원화 행방 투명화**: 실패 지점별로 사용자의 돈이 어디에 있는지(케이뱅크 미출금 / 업비트 잔류)를 상태·사유로 기록하고 UI에 고지합니다. 특히 매수 실패 시 "원화는 업비트 계좌에 안전하게 보관됨"을 반드시 안내합니다.
- **타임아웃 계층화**: 2차 인증 210초(미완료 시 재승인 가능 상태로 복구), 체결 추적 10분(초과 시 주문 취소로 시장 변동성 노출 차단), 승인 대기 24시간(자동 만료).

## 7. 화면 구성

화면별 상세 명세와 스크린샷은 `화면설명서/화면설명서.md` 참조. 앱은 하단 4탭 구조입니다.

| 탭 | 역할 | 핵심 화면 |

| 홈 | 자산 현황판 | 총 자산, 포트폴리오 도넛 차트, 보유 코인 실시간 시세 |
| 결제내역 | 소비·잔돈 관리 | 월별 통계, 소비 카테고리 차트, 결제 피드, **잔돈 투자 승인 플로우** |

| 설정 | 규칙·계정 관리 | 잔돈 규칙, 투자 성향, 카드/업비트 키 관리, 탈퇴 |

## 9. 기대 효과

- **사용자**: 번거로운 고민 없이 평범한 소비 생활만으로 자산 증식을 경험하고, 건별 승인·2차 인증·투명한 원화 행방 고지를 통해 변동성 자산에 대한 심리적 안전감을 유지합니다. 소비 통계와 투자 교육 콘텐츠로 금융 이해도가 함께 성장합니다.
- **기술적 증명**: 복잡한 외부 금융 API(업비트) 자격 증명을 다중 테넌트 환경에서 AES-256으로 안전하게 통제하는 보안 설계, 실 금융 트랜잭션에 준하는 상태 머신·멱등성·폴링 파이프라인 제어, LLM 비용을 구조적으로 절감하는 2-Tier/2-Stage 아키텍처 등 프로덕션 수준의 시스템 설계 역량을 증명합니다.
- **확장성**: 카드사 정규식 확장, 성향 축 추가, 추천 엔진 교체가 각각 독립적으로 가능한 구조로, MVP 이후의 사업 확장(Phase 2~3)을 코드 재설계 없이 수용할 수 있습니다.
