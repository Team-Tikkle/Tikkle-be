| 기능 ID | 기능명 | 설명 | 사전 조건 | 정상 흐름 (Happy Path) | 예외 및 에러 처리 / 데이터 힌트 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **FEAT-ONB-001** | 온보딩 및 성향 설정 | 회원가입 후 5축 투자 성향(설문) 및 카테고리별 다이나믹 잔돈 규칙을 설정합니다. | 앱 최초 설치 및 회원가입 완료 |1. 5축 투자 성향(하락장 방어 심리, 트렌드 민감도, 관심 코인 테마, 분산도, 밈 수용도) 설문 진행 후 속성 할당 <br> 2. 7대 표준 카테고리별 잔돈 규칙 개별 설정 <br> 3. MySQL DB 저장 및 실시간 결제 엔진 조회를 위한 Redis 캐싱 동기화 | **[예외]** 중도 이탈 시 다음 접속 때 해당 스텝부터 재개. <br> **[구현]** 별도 온보딩 API 없이 `PATCH /api/settings/profile`, `/spare-change-rules`, `/kbank`, `/upbit`를 순차 호출하는 방식. <br> **[Hint]** 잔돈 규칙 JSON: <br> `{ "category_rules": [{ "category": "CAFE", "rule_type": "ROUND_UP_10000" }, { "category": "MART", "rule_type": "ROUND_UP_50000" }, { "category": "FOOD", "rule_type": "ROUND_UP_10000" }, { "category": "SHOPPING", "rule_type": "PERCENT_10" }, { "category": "TRAFFIC", "rule_type": "ROUND_UP_10000" }, { "category": "CULTURE", "rule_type": "PERCENT_15" }, { "category": "ETC", "rule_type": "ROUND_UP_10000" }] }` (API 제약조건에 따라 7대 카테고리 모두 필수 포함) <br> **[RuleType]** `ROUND_UP_10000/20000/30000/40000/50000`, `PERCENT_10/15/20/25/30` |

Upbit 발급 Access Key, Secret Key 및 원화 입금 2차 인증 수단(TwoFactorProvider) 입력 <br> 2. 백엔드가 5대 필수 권한(자산조회/주문조회/주문하기/입금조회/입금하기)을 실제 Upbit API 호출로 검증 <br> 3. 검증 통과 시 AES-256 양방향 암호화 후 DB 저장 | **[예외]** 권한이 하나라도 누락되거나 키가 유효하지 않으면 `UPBIT-010`(401) 반환 및 재입력 유도. <br> **[정책]** 키 유효성은 **등록/수정 시점에만** 검증한다. 별도 유효성 플래그나 만료일 컬럼을 두지 않으며, 이후의 만료·권한 회수는 실제 Upbit API 호출이 401을 반환하는 시점에 감지된다. <br> **[보안]** API Key 평문 저장 절대 불가. |

| **FEAT-HOME-002** | 포트폴리오 요약 | 보유 중인 코인별 투자 비중을 파이 차트 등으로 시각화합니다. | 보유 코인 1개 이상 존재 | 1. Upbit API에서 보유 코인 리스트 및 매입가/평가액 호출<br>2. 코인별 비중(%) 산출 후 파이 차트 렌더링 | **[예외]** 아직 투자가 발생하지 않은 경우 빈 화면(Empty State) 디자인 노출. |

| 기능 ID | 기능명 | 설명 | 사전 조건 | 정상 흐름 (Happy Path) | 예외 및 에러 처리 / 데이터 힌트 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **FEAT-PAY-001** | 결제 및 잔돈 통계 리스트 | 결제 내역과 발생한 잔돈의 투자 상태(반영/미반영) 및 기간별 통계를 제공합니다. | 1회 이상 결제 푸시 수신 | 1. DB에서 조건별 데이터 조회 (월별/카테고리별 등)<br>2. 화면 상단에 총 결제금액, 총 투자 반영/미반영 잔돈 노출<br>3. 하단에 상세 결제 리스트 렌더링 | **[Hint]** 결제 요약 Table 필수 컬럼: total_payment, monthly_payment, total_invested_change, monthly_invested, total_uninvested, monthly_uninvested. |
| **FEAT-PAY-002** | 매수 승인 UI | 24시간 내에 배정된 종목에 대한 투자를 승인하는 UI입니다. 모든 매수는 사용자 승인을 거칩니다. | PENDING_PURCHASE 상태 결제 건 존재 | 1. 퀀트 엔진이 배정한 추천 종목(1개) 및 추천 사유 카드 노출<br>2. '투자 취소/거절'(`/reject`) 선택 시 미투자 잔돈으로 전환 (NOT_INVESTED) | **[예외]** 24시간이 경과한 건은 `PendingOrderExpirationScheduler`가 매시간 NOT_INVESTED로 정리하며 사유에 "매수 승인 대기 시간(24시간) 초과"를 기록한다. (EXPIRED 상태값은 존재하지 않는다.) <br>**[실시간]** 승인 후 파이프라인 진행 상황은 `GET /api/payments/{eventId}/stream` (SSE)로 수신한다. |

## 5. 투자 및 매매 시스템 엔진 (SYS)

결제 알림 수신 이후 카테고리 분류, 다이나믹 잔돈 계산, 시장 시간에 따른 하이브리드 매매 및 배치 제어를 담당하는 백엔드 코어 기능입니다.

| 기능 ID | 기능명 | 설명 | 사전 조건 | 정상 흐름 (Happy Path) | 예외 및 에러 처리 / 데이터 힌트 |
| --- | --- | --- | --- | --- | --- |
| **FEAT-SYS-001** | 결제 푸시 이벤트 보안 검증 | 안드로이드 앱이 스크래핑하여 전송한 결제 이벤트 데이터의 무결성과 보안을 검증합니다. | 푸시 알림 감지 및 서버 전송 완료 | 1. 결제 푸시 이벤트 데이터 서버 수신 <br>2. 요청 헤더에서 타임스탬프 및 암호화 서명 추출 <br>3. 전송 지연 시간(5분 이내) 확인 및 HMAC SHA-256 서명 무결성 검증 통과 | **[예외]** 타임아웃 만료 시 전송 지연 오류(401) 처리 <br>**[예외]** 서명 불일치 시 데이터 변조로 간주하여 차단 |
| **FEAT-SYS-002** | 3단계 Fail-Fast 트래픽 필터링 | 투자 가치가 없는 무의미한 결제 트래픽을 선제적으로 차단하여 시스템 자원을 보호합니다. | FEAT-SYS-001 보안 검증 통과 | 1. [중복 차단] 결제 고유 식별자(transactionId) 기반 중복 수신 여부를 Redis SETNX(`payment:tx:{id}`, 24h)로 판별 <br>2. [투자 비활성] 유저가 잔돈 투자를 꺼둔 경우 조기 종료(`PAYMENT-011`) <br>3. [카드 매칭] 사용자가 지정한 투자 타겟 카드와 결제 카드 일치 여부 판별 (불일치 시 `PAYMENT-008` 조기 종료) | **[중복]** 이미 처리된 식별자일 경우 `PAYMENT-009`(409) 반환. <br>**[중요]** 3건 모두 Redis 유저 설정 캐시만 조회하며 **원장 적재 이전에** 예외를 던진다. 즉 차단된 트래픽은 DB에 남지 않는다. |
| **FEAT-SYS-003** | 2-Tier 카테고리 분류 및 잔돈 정산 | DB 사전과 동기 AI를 혼합하여 가맹점을 분류하고, 확정된 카테고리의 룰에 따라 잔돈을 다이나믹하게 정산합니다. | FEAT-SYS-002 필터링 통과 | 1. [1차 분류] `PAYMENT_CATEGORY_MAPPING` 사전에서 가맹점명 부분 일치 검색 <br>2. [Cache HIT] 카테고리 즉시 확정 <br>3.
